# Выгрузка в Google Таблицу

Каждый прогон `qa check` добавляет данные на два листа (они создаются сами):

- **«Прогоны»** — одна строка на прогон: дата, версия, вердикт (ячейка подсвечена цветом), число провалов статики, холодный старт, память, крэши, тесты, причины;
- **«Проверки»** — по строке на каждую проверку и каждый тест прогона. Фильтр «Статус = Провал» за месяц покажет, что ломается чаще всего.

## Настройка (один раз, около 5 минут)

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект (или выберите существующий).
2. **APIs & Services → Library** → включите **Google Sheets API**.
3. **APIs & Services → Credentials → Create credentials → Service account**. Имя любое, роли не нужны.
4. Откройте созданный сервисный аккаунт → **Keys → Add key → JSON**. Скачанный файл переименуйте в `service_account.json` и положите рядом с `qa.yaml`. Файл уже в `.gitignore`, не коммитьте его.
5. Создайте Google Таблицу. Нажмите **«Настройки доступа»** и добавьте e-mail сервисного аккаунта (вида `qa-bot@<проект>.iam.gserviceaccount.com`, он есть в JSON-файле в поле `client_email`) с ролью **«Редактор»**.
6. В `qa.yaml`:

```yaml
google_sheets:
  enabled: true
  credentials_file: service_account.json
  spreadsheet: "https://docs.google.com/spreadsheets/d/1AbC...xyz/edit"   # ссылка или ID
```

7. Проверьте: `qa doctor --online`. Должно появиться «доступ к таблице есть».

Если корпоративная политика запрещает ключи сервисных аккаунтов, можно обойтись без API: файл `qa_runs/history.csv` (разделитель `;`, UTF-8) импортируется в таблицу через **Файл → Импорт**.

## Полезные приёмы в самой таблице

- Тренд холодного старта: выделите столбцы «Версия» и «Холодный старт, мс» на листе «Прогоны» → Вставка → Диаграмма.
- Топ падающих проверок: на листе «Проверки» → Данные → Сводная таблица. Строки — «Проверка», фильтр — «Статус = Провал», значения — COUNTA.

Если выгрузка не удалась, прогон всё равно завершится. Ошибка попадёт в консоль и в `summary.json → notes`.
