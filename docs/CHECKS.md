# Каталог проверок

Статусы: **Провал** (FAIL) · **Внимание** (WARN) · **Инфо** (INFO) · **OK** (PASS) · **Пропуск** (SKIP) · **Нестабилен** (FLAKY) · **Заблокирован** (BLOCKED).

Как выносится вердикт:
- **Не принимать** — есть хотя бы один провал в статике или на устройстве, не установилось приложение, либо упал тест с приоритетом из `verdict.blocker_priorities` (по умолчанию P0);
- **Принять с замечаниями** — есть предупреждения, упавшие P1/P2, нестабильные тесты, либо приложение не запускалось на устройстве;
- **Принять** — всё остальное.

Статус любой проверки можно переопределить в `static.severity_overrides`.

## Базовая проверка на устройстве

| ID | Проверка | Провал | Внимание |
|---|---|---|---|
| DV00 | Устройство и совместимость | — (Заблокирован: нет устройства, API ниже minSdk, нет подходящего ABI) | — |
| DV01 | Установка | ошибка `INSTALL_FAILED_*` | — |
| DV02 | Холодный старт (медиана N запусков `am start -W`) | ≥ `cold_start_fail_ms` или ошибка запуска | ≥ `cold_start_warn_ms` |
| DV03 | Приложение живо после старта (+скриншот) | процесс умер | процесс жив, но на экране не приложение |
| DV04 | Память (PSS) | — | Инфо |
| DV05 | Monkey-стресс (seed фиксирован, можно воспроизвести) | крэш или ANR | monkey прерван |
| DV09 | Крэши, ANR и нативные падения в logcat за весь прогон | есть хотя бы одно | — |

У каждого крэша в отчёте указан этап, на котором он случился (`install` / `launch` / `maestro` / `monkey`), и полный стектрейс. Его можно сразу прикладывать к багу.

## Сценарии Maestro

Тесты берут ID и приоритет из `properties` флоу. Упавший тест перезапускается `maestro.retries` раз: если со второй попытки он прошёл, статус «Нестабилен». Скриншот падения прикладывается к строке теста.
